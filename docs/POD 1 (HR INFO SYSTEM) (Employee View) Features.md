## **Left Sidebar (Navigation)** {#left-sidebar-(navigation)}

**What it does:** The sidebar is the main menu of the app. It sits on the left side of the screen and stays visible at all times, so users can jump between sections without getting lost or needing to go "back."

**What's in it:**

* **Navigation links** — the main sections/pages of the system (e.g., Home, Leave Request , Payslips , Reimbursement, Attendance, Profile including the benefits )  
* **Logged-in user info at the bottom** — shows who is currently logged in. This usually includes:  
  * The user's name and/or photo/avatar  
  * Their role or account type (if relevant)  
  * Access to their **profile** (clicking it lets them view/edit their account details, or log out)

## Top Bar {#top-bar}

**What it does:** The top bar sits above the main content area and stays visible on every page. It contains two key tools: a **search bar** and a **notification bell**.

### **a) Search Bar** {#a)-search-bar}

* Lets users search across the app instead of manually clicking through menus.  
* Should return relevant results quickly (e.g., a request, a record, a person, a document — whatever is searchable in the app).  
* Saves time for users who know what they're looking for but don't want to navigate multiple pages to find it.

### **b) Notification Bell** {#b)-notification-bell}

* Shows a **bell icon** with a **number badge** on it.  
* The number represents **how many items need the user's attention** right now (e.g., pending approvals, unread updates, action-required items).  
* Clicking the bell opens a list of those notifications/items.  
* Once the user views or resolves an item, the count goes down.

### **c) Toasts (Pop-Up Confirmations)** {#c)-toasts-(pop-up-confirmations)}

**What they are:** Toasts are small, temporary pop-up messages that appear briefly on the screen (usually in a corner) whenever something happens in the app. They disappear on their own after a few seconds.

**When they appear (examples):**

* A request is submitted → *"Your request has been submitted."*  
* A request is approved → *"Request approved."*  
* A payment goes through → *"Payment successful."*

## **Home/Dashboard**  {#home/dashboard}

---

The first screen employees see after logging in. Gives them a quick personal snapshot: attendance, leave, pay, and recent requests — all in one place.

**What's On It**

### **1\. Header / Greeting** {#1.-header-/-greeting}

* Shows the workspace label (e.g., "My space") and today's date  
* Personal greeting with the employee's first name (e.g., "Hi Maya 👋")

### **2\. Time Tracking Panel (main dark card)** {#2.-time-tracking-panel-(main-dark-card)}

* **Status indicator** — shows if the employee is "Clocked out" or "Clocked in," with a colored dot  
* **Live clock** — large running time display (HH:MM:SS)  
* **Status message** — e.g., "You haven't clocked in yet today."  
* **Action buttons:**  
  * Time In (primary button)  
  * Start Lunch  
  * Start Break  
  * Time Out (appears once clocked in)  
* **Today's summary** (right side of the card):  
  * IN time, OUT time, and total hours WORKED  
  * Lunch duration and Break duration for the day  
* **This Week table** — a mini weekly log showing each day (Mon–Fri), with time in, time out, and total hours per day. Today's row is highlighted.

### **3\. Leave Balance Cards** {#3.-leave-balance-cards}

* **Annual Leave** — shows used/total (e.g., "12.0 / 15 days"), with a progress bar and a note like "3 days used this year"  
* **Sick Leave** — same format (e.g., "9.0 / 10 days"), own progress bar and usage note  
* Each leave type gets its own card with a distinct progress bar color

### **4\. Next Payday Card** {#4.-next-payday-card}

* Shows the upcoming pay date (e.g., "Jul 15")  
* Includes pay frequency and payout details (e.g., "Semi-monthly · BPI •••• 4471")

### **5\. My Requests** {#5.-my-requests}

* List of the employee's recent submissions (e.g., Annual leave, Sick leave)  
* Each entry shows the type, date range, number of days, and status (Approved/Pending/Rejected) as a colored tag

## **Attendance Tab**  {#attendance-tab}

---

A page where employees (and their managers/HR) can see a full history of attendance, not just today's or this week's like the dashboard shows.

**What's On It**

### **1\. Calendar View** {#1.-calendar-view}

Based on Vite SEO's leave and holiday policies, here's a suggested color-coding legend for the calendar (Attendance and/or Leave Request tab):

**Holidays**

* 🟣 Purple — Regular Holiday (paid, no work required)  
* 🔵 Blue — Special Non-Working Holiday ("No Work, No Pay" unless approved)  
* 🟠 Orange — Special Working Holiday (regular wage, no premium)  
* 🟤 Brown/Dark Gray — Holiday worked with HR approval (flag to distinguish from a normal workday)

**Leave Types**

* 🟢 Green — Service Incentive Leave (SIL) — used for vacation/sick/personal  
* 🩵 Light Blue/Teal — Bereavement Leave  
* 🟡 Yellow — Emergency Leave  
* 🔴 Red — Unauthorized/Unexcused Absence (no documentation, undocumented emergency leave, failure to report bereavement, etc.)  
* ⚪ Gray — Non-working day / weekend

**Pending States**

* ⬜ Striped/Dashed border — Leave request pending approval (not yet confirmed, shown until HR/supervisor acts on it)

### **Notes Per Day (tied to the color)** {#notes-per-day-(tied-to-the-color)}

Each colored day can show a note on hover/click for context, e.g.:

* "Regular Holiday — Independence Day"  
* "SIL used — 1 day"  
* "Bereavement Leave — supporting document required"  
* "Emergency Leave — pending HR approval"  
* "Unauthorized absence — no documentation submitted"  
* 

### **3\. List/Table View (alternative to calendar)** {#3.-list/table-view-(alternative-to-calendar)}

* A simple row-by-row list of all attendance days: Date, Time In, Time Out, Hours Worked, Status, Note  
* Useful for exporting, printing, or reviewing a longer date range quickly

### **4\. Filter/Date Range** {#4.-filter/date-range}

* Employees can switch between months or select a custom date range to review past attendance

## **Leave Request Tab**  {#leave-request-tab}

---

A page where employees can file leave requests and track them, with built-in checks so they can't request more leave than they have.

**What's On It**

### **1\. Leave Request Form** {#1.-leave-request-form}

* **Type** — dropdown to pick leave type (Personal, Sick, Emergency, etc.)  
* **Dates** — select start and end date of the leave  
* **Half-day option** — toggle/checkbox if it's only a half-day (AM or PM)  
* **Reason** — text field for the employee to explain why they're taking leave

### **2\. Live Balance Check** {#2.-live-balance-check}

* As the employee fills out the form, the system automatically checks their remaining leave balance for that leave type  
* If the requested days exceed what's available, the system **blocks submission** and shows a warning (e.g., "You only have 2.0 sick leave days left")

### **3\. Personal Request History** {#3.-personal-request-history}

* A list of the employee's own past and pending leave requests  
* Shows type, dates, number of days, and status (Pending, Approved, Rejected)

### **4\. Automatic HR Notification** {#4.-automatic-hr-notification}

* Once submitted, the system automatically sends a notification to HR (and/or the direct manager) for approval

## **Payslips Tab** 

---

 {#payslips-tab}

A page with two panels: a list of pay periods on the left, and a full breakdown of the selected period on the right.

**What's On It**

### **1\. Header** {#1.-header}

* Title "Payslips" with a short subtext: "Populated automatically each time payroll runs"

### **2\. Pay Period List (left panel)** {#2.-pay-period-list-(left-panel)}

* A row for each pay period (e.g., "Jun 1-15, 2026")  
* Shows the date paid (e.g., "Paid Jun 15")  
* Shows Net Pay for that period  
* Status tag (e.g., "Paid")  
* Clicking a row loads its full breakdown on the right

### **3\. Payslip Detail View (right panel)** {#3.-payslip-detail-view-(right-panel)}

* **Header** — pay period dates, employee name and job title, and a "Download PDF" button  
* **Base pay** — regular salary for the period  
* **Allowances** — additional non-taxable/taxable pay, if any  
* **Deductions** (shown in red, itemized):  
  * Withholding tax  
  * SSS contribution  
  * PhilHealth  
  * Pag-IBIG  
  * Retirement (with rate shown, e.g., 4.8%)  
* **Net pay** — final take-home amount, bolded and highlighted  
* **Year-to-date summary** — YTD gross and YTD tax shown at the bottom

### **4\. Auto-Fill Each Payroll Run** {#4.-auto-fill-each-payroll-run}

* Every time payroll is processed, a new entry is automatically added to the list with all figures pre-filled — no manual encoding needed

### **5\. Download Option** {#5.-download-option}

* "Download PDF" button on the detail view lets employees save/print their payslip

## **Payroll Inquiry** {#payroll-inquiry}

Employees submit inquiries via a "Request Inquiry" button; HR manages a Pending → In Progress → Done queue and follows up via Telegram.

**What's On It**

### **1\. Request Inquiry Button** {#1.-request-inquiry-button}

* A button employees click to submit a new payroll-related question or concern  
* Opens a form where they can describe the issue (e.g., wrong deduction, missing pay period, tax question)  
* May include fields like: subject/topic, related pay period, description, and optional attachment (e.g., screenshot of payslip)

  ### **2\. Inquiry List / History** {#2.-inquiry-list-/-history}

* Shows all inquiries the employee has submitted  
* Each entry displays the subject, date submitted, and current status

### **3\. Status Tracking** {#3.-status-tracking}

* Each inquiry moves through three stages, visible to the employee:  
  * **Pending** — newly submitted, not yet reviewed  
  * **In Progress** — being looked into  
  * **Done** — resolved/closed

### **4\. Telegram Follow-Up** {#4.-telegram-follow-up}

* HR follows up with the employee via Telegram to discuss or resolve the inquiry  
* The portal status still updates to reflect where the inquiry stands, even though the conversation itself happens on Telegram

## **Reimbursement Tab**

---

 {#reimbursement-tab}

File a reimbursement (category, amount, description, receipt) and track its status. Routes to HR on submit.

**What's On It**

### **1\. Reimbursement Form** {#1.-reimbursement-form}

* **Category** — dropdown to select type of expense (e.g., Transportation, Meals, Office Supplies, Medical, Internet/Communication)  
* **Amount** — the peso amount being claimed  
* **Description** — text field to explain what the expense was for  
* **Receipt** — upload/attach a photo or file of the receipt as proof

### **2\. Submit Button** {#2.-submit-button}

* Sends the reimbursement request directly to HR for review once filed

### **3\. Request List (side panel)** {#3.-request-list-(side-panel)}

* Shows all reimbursement requests the employee has submitted  
* Each entry displays category, amount, date filed, and status  
* Status tags to track progress (e.g., Pending, Approved, Rejected, Paid)  
* Clicking an entry can show the full details (description, receipt attached, notes if rejected)

## **Profile Tab**

---

 {#profile-tab}

Contains the employee's 201 file — personal information and benefits. Includes a button to request access if needed.

**What's On It**

### **1\. Request Access Button** {#1.-request-access-button}

* Button at the top of the tab for employees who need to request access to view/manage their 201 file (e.g., if access is restricted by default or needs re-authorization)

### **2\. Profile Section** {#2.-profile-section}

* Displays the employee's own information (e.g., name, contact number, address, emergency contact, bank account, employment details)  
* Employees can submit edits, but **nothing changes directly** — every edit is sent as a request to HR  
* **Standard fields** (phone, address, emergency contact) — click "Change Request" to send to HR for review and approval  
* **Sensitive fields** (bank account, legal name) — also go to HR, may require additional verification/documentation before approval  
* Changes only take effect once HR verifies and approves the request  
* A "Pending Changes" indicator can show which fields have a request awaiting HR actio

### **3\. Benefits Section** {#3.-benefits-section}

* **Read-only view** of the employee's own enrolled plans (e.g., HMO, life insurance, retirement plan)  
* Employees can see their current coverage/enrollment details but cannot edit anything here  
* Changes to benefits enrollment are only possible during the **next open enrollment window** (not available on-demand)
